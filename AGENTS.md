# Инструкции агенту · EDIT

## LLM: ровно один запрос в линейке

**Жёсткое правило.** В одной линейке задачи (книга → темы+оценка, или
аналогичный проход) делай **ровно один** LLM-запрос.

- Не дроби книгу/корпус на главы, сегменты, чанки.
- Не батчи shortlist отдельными вызовами.
- Не запускай «A2, потом отдельно B1», «сначала майнинг, потом скоринг»,
  «потом ещё прогон по 15 темам» — без явного согласия пользователя.
- Не устраивай массовые серии запросов «на всякий случай» и без спроса.

**Исключения (можно без спроса):**
1. ретраи того же запроса при transient-ошибке провайдера;
2. пользователь **явно** разрешил второй шаг / батч / дробление.

Если модель не тянет длинный вход — смени модель на long-context, **не**
режь текст на N вызовов. Для whole-book A1/A2+B1 (темы/теги):
`topic_pass_model` = `gemini-2.5-flash`. Редактура E/C/D/E-check:
`gpt-5-2` → `gemini-3-6-flash` → `gemini-3.5-flash` (2.5 только аварийный хвост).
C1.5 research: Gemini + `tools: googleSearch` на KIE (`research_enrich_model`);
статья/бриф — контекст, факты — новые из поиска, не пересказ.

A1-сегментация — локальный preprocessing без LLM, не повод плодить вызовы.

Стоимость и контроль: один длинный input дешевле и предсказуемее десятков
коротких с повторной загрузкой источника.
