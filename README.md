# Редакционный конвейер научпоп-канала (рабочее имя: EDIT)

> Master-документ проекта. Агент читает его первым. Отдельные узлы описаны в
> тикетах `EDIT-*.md`. Здесь — что мы строим, зачем, из чего состоит и какие
> инварианты нельзя нарушать.
>
> **База выбрана — см. `EDIT-ADR-002`** (заменяет ADR-001). Проект строится как
> **LangGraph-граф** на базе `langchain-ai/content-writer`, стек — **Python +
> Pydantic**. Фактчек — лёгкий (одна развилка «не выдумано ли»), картинки —
> пачкой из веб-поиска, отбор и права — вручную на монтаже, вне графа.

---

## 1. Что это

Автоматизированная **редакция** для канала о визуальной культуре: короткие
видео (рилсы/Shorts, 60–90 сек) о том, ПОЧЕМУ визуал — в моде, дизайне,
анимации — выглядит именно так. Не «что это» и не «как сделано». Причина, а не
техника.

Вход конвейера — книга или научная статья (теория моды, история дизайна,
история анимации). Выход — готовый к продакшену сценарий с раскадровкой,
привязанной к архивным изображениям.

**Границы проекта.** Продакшен-слой (TTS, генерация/подбор картинок, монтаж)
уже существует как отдельная агентская система и в этот проект НЕ входит. EDIT
заканчивается на артефакте, который принимает продакшен: сценарий + shot list.
Всё, что делает EDIT, — превращает источник в этот артефакт так, чтобы ролик
досматривали, пересылали и сохраняли.

**Почему это отдельный проект.** Редактура — это не один агент «напиши
сценарий». Это конвейер из специализированных узлов с конфликтом интересов
(добытчик тезисов, фактчекер, сценарист, критик), между которыми ходят
типизированные артефакты. Ценность — в границах между узлами и в контрактах,
а не в отдельной модели.

---

## 2. Зачем (цель, выраженная в метриках)

KPI канала — рост подписчиков — лаговый и шумный. Конвейер оптимизирует три
опережающих сигнала, на которые он реально влияет:

- **Досмотр** — решается на этапе ОТБОРА темы (B) и на критике удержания (E2),
  не монтажом.
- **Пересылки** — решаются наличием «социальной валюты»: даёт ли ролик статус
  тому, кто им поделится. Проверяется тестом пересказа (E5).
- **Сохранения** — прямой индикатор «стал умнее»; обеспечивается
  доказательностью (досье + архив).

Всё, что узел делает, должно вести к одному из трёх. Узел, который не двигает
ни один, — лишний.

---

## 3. Архитектура: этапы и артефакты

Конвейер — направленный граф из семи слоёв. Между слоями ходят Pydantic-модели.
Каждый слой либо обогащает артефакт, либо отвергает его (hard fail) и
возвращает назад.

```
A. ДОБЫЧА
   A1 Сегментация источника        source → source_map
   A2 Майнер тезисов               source_map → list[ClaimCard]     ← тикет EDIT-A2
   A3 Дедуп                        против выпущенного + карты конкурентов

B. ОТБОР  (здесь решается досматриваемость)
   B1 Скоринг                      ClaimCard → ScoredClaim (5 осей)
   B2 Решение — ЧЕЛОВЕК            выбор из ранжированного списка

C. МАТЕРИАЛ  (упрощён — см. ADR-002)
   C1 Сборщик материала           +веб-подтверждение тезиса (лёгкое)
   C2 Поиск картинок              пачка из Brave/Pinterest/Google на фразу,
                                  критерий = описание/метаданные ≈ запрос.
                                  ОТБОР и права — вручную на монтаже, вне графа
   C3 Мягкая проверка фактов      одна LLM-развилка: «нет ли выдуманных
                                  дат/имён/атрибуций». НЕ SAFE, не движок
   →  Dossier ЗАМОРАЖИВАЕТСЯ (SSOT)

D. СЦЕНАРИЙ
   D1 Архитектор структуры         Dossier → BeatList (с таймкодами!)
   D2 Прозаик                      пишет ТОЛЬКО из досье, каждый факт → claim_id
   D3 ToV-агент                    отдельный проход по словарю персонажа

E. РЕДАКТУРА  (ядро проекта)
   E1 Аудитор трассируемости       каждый факт → claim_id, иначе fail
   E2 Критик удержания             ScriptDraft → RetentionReport      ← тикет EDIT-E2
   E3 Красный критик               враждебная установка: «разнеси»
   E4 Перебор открытий             5-8 вариантов первых 3 сек, выбор
   E5 Тест пересказа               пересказ одним предложением → кода
   E6 Сжатие                       -20-25% длины без потери смысла
   E7 Идеатор (разгон)             Dossier+Script → IdeaProbe: концепт поверх    ← тикет EDIT-E7
                                   факта, МАРКИРОВАН как мнение. Константа
                                   формата; вкл/выкл — ЧЕЛОВЕК на финале

F. ВЫХОД
   F1 Раскадровка                  каждая фраза → пачка картинок из веб-поиска.
                                   Отбор слоёв — человек на монтаже, не граф
   F2 Вычитка вслух — ЧЕЛОВЕК

G. ПЕТЛЯ
   G1 Пост-аналитик                метрики отвала/шеров → веса B1, промпт E2
```

## 4. Инварианты (нарушать нельзя)

Это конституция проекта. Любой узел, любой рефакторинг им подчиняются.

1. **Досье замораживается перед сценарием.** После C3 `Dossier` неизменяем.
   Сценарист (D2) физически не имеет источника фактов, кроме досье. Даже при
   лёгкой проверке (ADR-002) это барьер против выдуманных датировок и
   атрибуций — сценарист не дописывает факты «от себя».

2. **Роли с конфликтом интересов — РАЗНЫЕ вызовы, разные промпты.** Сценарист
   хочет красиво. Критик хочет разорвать. Фактчекер не должен видеть сценарий.
   Если слить их в один промпт, получится вежливая серость: модель по
   умолчанию — соглашающийся собеседник.

3. **Дешёвые гейты раньше дорогих.** Отсев на скоринге (B) стоит копейки, отсев
   после написания — потерянный цикл добычи+обоснования+сценария. Порядок
   слоёв менять только в сторону «дешёвая проверка раньше».

4. **Человек в трёх точках:** выбор темы (B2), включение/выключение разгона
   (E7) и финальная вычитка вслух (F2). Вкус — тянет ли тема идейный разгон,
   звучит ли это живым человеком — не автоматизируется. Всё между — конвейер.

5. **Единица работы — причинный тезис с разрывом ожидания**, не «интересный
   факт». Тезис без `counter_expectation` и без `visual_hint` не входит в
   производство. Это то, что держит канал в свободной нише и не даёт сползти к
   занятым конкурентам («что изображено» / «как сделано»).

6. **Каждый факт в сценарии трассируется до `claim_id`.** Нет ссылки — hard
   fail на E1. Галлюцинации ловятся структурно, а не вычиткой.

7. **Факт и мнение — разные потоки, мнение маркировано.** Тело держит факт
   (трассируется, проверяется). Идейный разгон (E7) — мнение поверх факта,
   якорится в `claim_id`, но подаётся как гипотеза-оптика и слышимо помечается
   в озвучке. Фактчек (C3) разгон не трогает — он непроверяем по замыслу.
   Смешать их — значит продавать домысел под пруф; на этом канал теряет доверие
   аудитории.

## 5. Сквозные сущности

Живут в `models/`, импортируются всеми слоями. Порядок реализации — снизу вверх
по зависимостям.

| Модель | Появляется | Замораживается | Кто читает |
|---|---|---|---|
| `ClaimCard` | A2 | — | B1, C1 |
| `ScoredClaim` | B1 | после B2 | C1 |
| `Dossier` | C1-C3 | **после C3** | D1, D2, E1, F1 |
| `BeatList` | D1 | — | D2, E2 |
| `ScriptDraft` | D2 | — | E1-E6 |
| `RetentionReport` | E2 | — | E4, E6 |
| `IdeaProbe` | E7 | — | F1, продакшен (текст-разгон) |
| `ShotList` | F1 | передаётся в продакшен | внешний слой (пачки картинок на фразу) |

Единый идентификатор через весь конвейер — `claim_id` (slug, стабильный).
По нему трассируется всё: от тезиса в источнике до фразы в раскадровке.

## 6. Дорожная карта реализации

Порядок продиктован зависимостями и правилом «сначала докажи, что тема
взлетит». База (content-writer) даёт writing-каркас; слой C упрощён (ADR-002).

**Веха 0 — поднять базу.** Склонировать `content-writer` (Python-бэкенд),
прогнать его writing-агент как есть, понять граф, state и механику ассистентов.
Ничего не менять. Определить Pydantic-схемы `models/` под наши артефакты
(контракты A2/E2 — как в тикетах, без изменений).

**Веха 1 — вертикальный срез на одном тезисе.**
Реализовать A2 (майнер тезисов) и E2 (критик удержания) по готовым тикетам.
Остальное — ручные заглушки: тему выбираешь сама, материал собираешь руками,
сценарий пишешь сама, гоняешь через E2. Цель — доказать, что A2 даёт годные
ПРИЧИННЫЕ тезисы, а E2 ловит отвал.

**Веха 2 — материал и трассируемость (упрощена).** Лёгкий узел C1 (сбор +
веб-подтверждение), C2 (пачка картинок из веб-поиска), C3 (мягкая проверка
фактов одной развилкой) + E1. Здесь появляется **заморозка досье**. Прав,
Open Access, SAFE-верификации — НЕТ (см. ADR-002). После вехи система собирает
материал и не тащит явных выдумок.

**Веха 3 — генерация сценария.** D1-D3. D1 обязан отдавать таймкоды — без них
E2 не на чем работать. Нет таймкодов — блокер для E2.

**Веха 4 — полная редактура.** E3-E6. Узлы, напрямую делающие ролик вирусным,
доноров нет. E4 (перебор открытий) — следующий по приоритету после A2/E2.

**Веха 5 — петля.** G1 + F1. Замкнуть метрики отвала в веса B1. F1 отдаёт пачки
картинок на фразу; отбор — вручную на монтаже. До ~15-20 роликов веса и пороги —
гипотеза; вердикты E2 воспринимать как «список подозрений».

## 7. Технические конвенции

- **Стек — Python, LangGraph** (база content-writer, см. ADR-002). Один
  рантайм.
- **Каждый слой — узел графа**, состояние — типизированный LangGraph state.
  Гейты — условные рёбра; человек в петле (B2, F2) — `interrupt`.
- **Контракты между узлами — Pydantic v2.** Между узлами ходит валидированный
  объект. Невалидный артефакт не «чинится» на лету — логируется и отвергается.
- **Заморозка досье — иммутабельная ветка state** после C3. Граф сам не
  запретит поздний узел дописать; это инвариант, за которым следим в code
  review, а не только рантаймом.
- **Пороги и веса — в конфиг, не в код.** dropoff_score, оси скоринга, длины —
  калибруемое. Первые прогоны меняют эти числа часто.
- **Каждый узел детерминирован по контракту, не по тексту.** Один вход даёт
  стабильный ВЕРДИКТ (passes/fail, состав полей), даже если формулировки
  плавают. Тесты проверяют вердикт, не дословный вывод.
- **LLM-узлы возвращают только структурированный вывод** под Pydantic-схему,
  без преамбулы; парсинг строгий.
- **Проверка фактов — лёгкая, картинки — пачкой.** C3 не движок, а одна
  развилка. Отбор изображений и права — вне графа, на человеке (ADR-002).

## 8. Открытые вопросы (решить по ходу)

- Формат `source_map` (A1): три стратегии реализованы
  ([`docs/EDIT-A1-segmentation.md`](docs/EDIT-A1-segmentation.md));
  **финальный default** — после ручной оценки матрицы на реальной главе
  (`runs/*/NOTES.md`). Сейчас provisional: `semantic`.
- Мультиязычность: на A1 перевод **не** делаем — цитаты в оригинале;
  `SourceMap.language` только метка (`ru`/`en`).
- Насколько мягкой должна быть проверка C3: только явные выдумки (даты/имена)
  или чуть шире. Калибруется на первых роликах, не умозрительно.
