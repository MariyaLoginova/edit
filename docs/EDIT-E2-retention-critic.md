# EDIT-E2 · Критик удержания (retention critic)

**Слой:** редакция / вычитка (E2)
**Вход:** `ScriptDraft` (бит-лист + проза после D3, с таймкодами по секундам)
**Выход:** `RetentionReport`
**Зависит от:** D-слой (сценарий) готов, есть привязка текста к секундам
**Блокирует:** F (раскадровка) — ролик не уходит в продакшен, пока не закрыты dropoff-маркеры выше порога

---

## Зачем узел

Досматриваемость решается не монтажом, а тем, есть ли на каждой секунде причина смотреть дальше. Узел проходит сценарий по секундам и на каждой отвечает на один вопрос: **«зачем зрителю оставаться ещё секунду?»** Секунды без ответа — точки отвала. Это перевод расплывчатого «сделай повируснее» в пооперационную карту слабых мест.

Узел не переписывает — он **диагностирует**. Правки делает E4 (перебор открытий) и E6 (сжатие) по его отчёту. Разделение намеренное: критик, который сам чинит, начинает защищать свои правки и теряет строгость.

## Контракт (Pydantic v2)

```python
from enum import Enum
from pydantic import BaseModel, Field


class DropReason(str, Enum):
    slow_open = "slow_open"            # первые 3 сек без крючка / раскачка
    no_forward = "no_forward"          # нет причины смотреть дальше, «плато»
    front_loaded_payoff = "front_loaded_payoff"  # интрига раскрыта слишком рано
    second_thesis = "second_thesis"    # появился второй тезис — расфокус
    abstract = "abstract"              # ушли в абстракцию без объекта на экране
    filler = "filler"                  # вводные слова, «в этом видео мы», связки-пустышки
    unpaid_setup = "unpaid_setup"      # обещание/вопрос без последующего ответа
    flat_ending = "flat_ending"        # кода не сворачивается в цитируемую фразу


class BeatRisk(BaseModel):
    t_start: float = Field(..., ge=0, description="Секунда начала фрагмента")
    t_end: float = Field(..., ge=0, description="Секунда конца фрагмента")
    quote: str = Field(..., min_length=1, description="Кусок сценария, к которому относится риск")
    reason: DropReason
    forward_question: str | None = Field(
        None,
        description="Какой вопрос держит зрителя на этом фрагменте. None = отвал: держать нечем."
    )
    severity: int = Field(..., ge=1, le=5, description="1 — придирка, 5 — гарантированный отвал")
    fix_hint: str = Field(..., min_length=1,
                          description="Что сделать. НЕ переписанный текст — направление для E4/E6.")


class RetentionReport(BaseModel):
    script_id: str
    duration_sec: float

    first3_has_hook: bool = Field(..., description="Есть ли крючок в первые 3 секунды")
    open_strength: int = Field(..., ge=1, le=5, description="Сила открытия")

    risks: list[BeatRisk]

    dropoff_score: int = Field(
        ..., ge=0, le=100,
        description="Интегральная оценка риска отвала. Выше = хуже. Порог блокировки задаётся в конфиге."
    )
    passes: bool = Field(..., description="dropoff_score ниже порога И нет risks с severity>=4")
    summary: str = Field(..., max_length=400, description="Где именно теряем зрителя, 2-3 фразы")
```

**Правило блокировки:** `passes == False` → ролик не уходит в F. Любой `BeatRisk` с `severity >= 4` держит ролик независимо от интегрального балла — один гарантированный отвал важнее хорошего среднего.

## Системный промпт узла (черновик)

```
Ты — критик удержания короткого видео. Не редактор, не автор. Твоя работа —
найти, ГДЕ ИМЕННО зритель перестанет смотреть, и объяснить почему. Ты не
переписываешь текст.

Тебе дают сценарий с таймкодами по секундам. Иди по нему фрагмент за
фрагментом. На каждом фрагменте ответь на ОДИН вопрос:
«Что заставляет зрителя смотреть следующую секунду?»

Если ответа нет — это точка отвала, зафиксируй BeatRisk с forward_question=null.

Особое внимание:
— Первые 3 секунды. Если там раскачка, приветствие, «в этом видео» — это
  slow_open, severity не ниже 4. Крючок должен быть в первом кадре.
— Плато: несколько секунд подряд без нового витка — no_forward.
— Ранний payoff: если интрига раскрыта, а до конца далеко — дальше смотреть
  незачем. front_loaded_payoff.
— Второй тезис: короткое видео держит один. Появился второй — second_thesis.
— Абстракция без объекта на экране: зрителю не на что смотреть — abstract.
— Обещание без ответа: задали вопрос/интригу и не закрыли — unpaid_setup.
— Концовка: если не сворачивается в одну цитируемую фразу — flat_ending.

Будь строг. Твоя цель — чтобы 40 секунд держали, а не чтобы автору было
приятно. Лучше отметить лишнее, чем пропустить отвал.

Оцени severity честно: 5 — почти каждый уйдёт здесь; 1 — мелкая придирка.
fix_hint — это НАПРАВЛЕНИЕ («перенеси раскрытие ближе к концу»), а не готовый
переписанный текст.

Верни ТОЛЬКО JSON по схеме RetentionReport, без преамбулы.
```

## Критерии приёмки

- [ ] На заведомо слабом сценарии (медленное открытие, второй тезис в середине) узел ставит `first3_has_hook=false`, ловит `second_thesis` и выдаёт `passes=false`.
- [ ] На заведомо сильном (крючок в первом кадре, один тезис, кода-фраза) — `passes=true`, `risks` пустой или только severity 1-2.
- [ ] Каждый `BeatRisk` привязан к реальному фрагменту сценария (`quote` — подстрока входа).
- [ ] `forward_question=null` появляется только там, где действительно нет тяги вперёд (ручная сверка на 5 фрагментах).
- [ ] Любой `severity>=4` даёт `passes=false` независимо от `dropoff_score`.
- [ ] Прогон одного сценария дважды даёт стабильный вердикт `passes` (не прыгает true/false между запусками).
- [ ] Отчёт машиночитаем: E4/E6 могут взять `risks` и адресно править, не читая прозу.

## Замечания к реализации

- Порог `dropoff_score` — в конфиг, не хардкод. Первые 15-20 роликов это гипотеза; калибруется на реальных данных отвала из G1 (пост-аналитик). До накопления данных воспринимать вердикт как «список подозрений», а не приговор.
- Держать узел ДИАГНОСТИЧЕСКИМ. Как только он начнёт возвращать переписанный текст, он перестанет быть строгим — будет защищать свои формулировки. Правки — на E4/E6.
- `forward_question` — сердце узла. Это не метаданные, это сам метод: заставить критика на каждой секунде назвать причину остаться. Пустое поле = найденный отвал.
- Не путать с E3 (красный критик). E3 бьёт по СОДЕРЖАНИЮ («банально, не следует из посылки»). E2 бьёт по ДИНАМИКЕ («здесь уйдут»). Тезис может быть сильным (E3 доволен), а подан так, что отваливаются (E2 блокирует) — и наоборот.
- Секундная привязка требует, чтобы D-слой отдавал таймкоды. Если их нет — это блокер выше по потоку, завести отдельным тикетом на D.
