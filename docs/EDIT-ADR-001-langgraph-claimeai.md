# ADR-001 · База: ClaimeAI / LangGraph как ядро редакционного конвейера

**Статус:** ЗАМЕНЁН ADR-002 (оставлен в истории)
**Дата:** 2026-08
**Контекст решения:** выбор технической базы для проекта EDIT (редакционный конвейер научпоп-канала)

> **Не использовать как актуальную базу.** См.
> [`EDIT-ADR-002-content-writer.md`](EDIT-ADR-002-content-writer.md): стек —
> content-writer / LangGraph / Python; строгий SAFE-фактчек и слой прав сняты.

---

## Контекст

EDIT превращает источник (книга/научная статья по теории моды, истории дизайна,
анимации) в готовый к продакшену сценарий. Продакшен-слой (TTS, картинки,
монтаж) уже существует отдельно и в проект не входит.

Ядро проекта — не генерация видео, а **редакция**: извлечение проверяемых
тезисов, фактчек, критика удержания. Обзор опенсорса показал, что поле делится
на два непересекающихся класса:

1. **Видео-продакшен-каркасы** (prompt-to-video, AgentCut, ViMax, MovieAgent,
   youtube-autopilot) — делают ровно то, что у нас уже готово. Как донор ядра
   бесполезны: дадут второй продакшен, не дадут редакцию.
2. **Фактчек-пайплайны** (ClaimeAI, реализации Claimify, SAFE) — делают ровно
   нашу самую рискованную и дорогую в разработке часть: извлечение
   деконтекстуализированных утверждений и их независимую верификацию.

Наш пайплайн — гибрид, которого в опенсорсе как целого нет. Значит, базу надо
выбирать по САМОМУ рискованному слою, а не по самому объёмному.

---

## Решение

**Берём ClaimeAI (LangGraph, MIT) как базу ядра. Строим EDIT как LangGraph-граф,
переиспользуя extractor и verifier ClaimeAI как отправную точку слоёв A и C.**

Обоснование выбора именно этой базы, а не youtube-autopilot:

- Самый большой технический риск проекта — **галлюцинация фактов** (выдуманные
  датировки, атрибуции). Это убивает научпоп-канал в глазах аудитории
  дизайнеров/режиссёров быстрее, чем слабый монтаж. ClaimeAI решает именно это,
  причём по опубликованной методологии (Claimify, Microsoft Research 2025;
  SAFE, DeepMind 2024), а не наивным промптом.
- **Изоляция фактчекера встроена архитектурно.** В ClaimeAI `claim_verifier`
  видит только утверждение, не исходный текст. Это ровно наш инвариант
  «фактчекер не видит сценарий» — не надо его выстраивать, он уже есть в форме
  графа.
- **LangGraph даёт граф с типизированным state, ветвлением и human-in-the-loop
  из коробки.** Наши инварианты «дешёвые гейты раньше дорогих» и «человек в двух
  точках» — это узлы графа с условными рёбрами и interrupt, а не самописная
  оркестрация.
- Каркас youtube-autopilot решал бы задачу оркестрации, которую LangGraph
  закрывает лучше и стандартнее. Его ценные идеи (двухгейтовый ревью,
  YAML-пороги, anti-repeat память) переносятся в граф как паттерны, без клона
  кода.

## Что берём, что адаптируем, что пишем сами

| Слой EDIT | Источник | Действие |
|---|---|---|
| Оркестрация, state, гейты, interrupt | **LangGraph** | база, используем как есть |
| A2 майнер тезисов | **ClaimeAI `claim_extractor` + Claimify** | АДАПТИРУЕМ: Claimify извлекает проверяемые утверждения; мы добавляем поля `counter_expectation` и `visual_hint` и фильтр «только причинные тезисы о визуале» |
| C3 фактчекер | **ClaimeAI `claim_verifier` + SAFE** | АДАПТИРУЕМ: verifier с вердиктами supported/refuted/not-enough-info; заменяем/дополняем источники под наш домен (архивы, а не только веб) |
| C1 ресёрчер, C2 архивариус | ClaimeAI verifier (частично) | РАСШИРЯЕМ: verifier ищет подтверждение; C2 дополнительно тянет изображение с правовым статусом |
| B скоринг вирусности | — | ПИШЕМ САМИ: доноров нет |
| D сценарий | — | ПИШЕМ САМИ |
| E критик удержания, красный критик, тест пересказа | — | ПИШЕМ САМИ: это ров продукта, опенсорса нет |
| Двухгейтовый ревью, YAML-пороги, anti-repeat | youtube-autopilot (паттерн) | ПЕРЕНОСИМ как паттерн в узлы графа, код не клонируем |

**Ключевая мысль:** ClaimeAI закрывает слои A и C — то, что рискованно и уже
решено наукой. Слои B/D/E (отбор вирусных тем, сценарий, критика удержания)
доноров не имеют и остаются нашей уникальной работой. Мы не пишем с нуля
опасную часть и вкладываем силы туда, где создаём отличие.

## Последствия

### Стек
- **Язык — TypeScript, LangGraph.js**, как в ClaimeAI. Не смешиваем с Python,
  чтобы не держать два рантайма ради одного графа.
- **Контракты между узлами — Zod-схемы** (нативны для LangGraph.js state),
  а не Pydantic. Ранее набросанные на Pydantic контракты A2/E2
  ПЕРЕПИСЫВАЮТСЯ на Zod. Смысл полей сохраняется — меняется только язык схемы.
- Поиск-провайдер: ClaimeAI использует Tavily. Оставляем на C-слое, для C2
  (архивы) добавляем прямые коннекторы к Open Access API (Met, Rijksmuseum,
  Smithsonian, Wikimedia Commons) — см. исследование, юридический блок.

### Что упрощается
- Слои A и C стартуют не с нуля, а с рабочей референс-реализации.
- Инвариант «фактчекер изолирован» и human-gates — из коробки LangGraph.
- Голосование для снятия неоднозначности и multi-retry верификации — уже есть в
  ClaimeAI, не изобретаем.

### Что усложняется / риски
- ClaimeAI заточен под фактчек «true/false по веб-доказательствам». Наш A2 —
  не просто извлечение утверждений, а извлечение ПРИЧИННЫХ тезисов о визуале с
  разрывом ожидания. Это надстройка над Claimify, а не он сам: поля
  `counter_expectation` / `visual_hint` и жанровый фильтр — наша работа поверх.
- Домен verifier'а — общий веб. Для нашего домена (история дизайна, атрибуции,
  датировки из архивов) веб-поиска мало; C2 должен уметь тянуть первоисточник
  из музейных Open Access, а не только Tavily-сниппет.
- Мы наследуем чужие креативные допущения ClaimeAI (voting, retry-логика).
  Проверить на нашем материале, что они не режут причинные тезисы как
  «непроверяемые».
- Заморозка досье (наш инвариант) в графе выражается как **неизменяемая ветка
  state после узла C3**. LangGraph это позволяет, но за иммутабельностью надо
  следить руками — граф сам не запретит поздний узел дописать в state.

### Что отклонено
- **youtube-autopilot как база** — решает оркестрацию, которую LangGraph
  закрывает лучше; его редакция картонная (один ScriptWriter, нет фактчека,
  нет критика удержания). Идеи берём, код нет.
- **Голый LangGraph с нуля** — отбросили бы готовую референс-реализацию A и C,
  где сосредоточен главный риск. Нет причин отказываться от работающего
  extractor/verifier.
- **Полностью своё с нуля по README** — переизобретение Claimify/SAFE, самая
  дорогая и рискованная часть, ради иллюзии контроля.

## Открытые вопросы (в реализацию)
- Формат `source_map` (A1): по главам / абзацам / смысловым блокам — влияет на
  гранулярность A2. Решается на реальной книге.
- Где переводить англоязычные источники (часть теории моды) — на A1 или хранить
  цитаты в оригинале в `citation.quote`.
- C2: отдельный узел проверки прав на изображение или поле `rights` внутри
  архивариуса. Пока — поле, вынести если логика разрастётся.
