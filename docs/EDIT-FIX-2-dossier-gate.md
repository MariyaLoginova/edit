# EDIT-FIX-2 · C-слой: непустое досье как условие заморозки

**Приоритет:** 2 из 3 (после FIX-1)
**Меняет:** C1/C2/C3, условие freeze, вход D2
**Зависит от:** FIX-1 (новый контракт `ClaimCard` с `contrast_pair`)

---

## Диагноз

В провалившемся прогоне досье было пустым: `material_notes=""`,
`web_confirmations=[]`, `image_candidates=[]`. C3 честно заморозил пустышку,
freeze прошёл, D2 честно написал «только из досье» — а в досье не было ничего,
кроме claim, одной цитаты и списка имён. Отсюда пересказ вместо разбора.

Тут ДВА разных отказа, и их надо чинить порознь:

1. **Баг.** `image_candidates=[]` — поиск картинок не отработал (не подключён,
   упал, или ошибка проглочена молча). Пустой список выглядит как «ничего не
   нашлось», а на деле это несработавшая интеграция.
2. **Дыра в контракте.** Даже если поиск сломан, пустое досье не должно
   проходить freeze. Инвариант «дешёвые гейты раньше дорогих» есть в README, но
   на этом стыке не реализован.

---

## Часть 1 — починить сбор

- Проверить интеграцию поиска картинок: ключ, квота, реальный ответ.
- **Ошибка поиска = явный fail узла, а не пустой список.** Молча проглоченное
  исключение — то, что позволило пустоте доехать до D. Логировать причину.
- Различать в состоянии два случая: «поиск отработал, нашёл 0» и «поиск не
  отработал». Сейчас они неразличимы, а лечатся по-разному.

## Часть 2 — картинки под A/B

После FIX-1 у карточки есть `contrast_pair` (state_a / state_b). Средняя часть
ролика показывает ОБА состояния — значит и картинки нужны на оба.

- `image_candidates` группируется по состояниям: `for_state_a[]`, `for_state_b[]`.
- Запрос на поиск строится из `state_a` / `state_b`, а не из общего `claim`.
- Мягкая проверка соответствия остаётся прежней (описание/метаданные ≈ запрос),
  ужесточать не нужно.

## Часть 3 — гейт freeze (hard fail)

C3 не замораживает досье, если не выполнено ВСЁ:

```python
def can_freeze(d: Dossier) -> tuple[bool, list[str]]:
    problems = []
    if not d.material_notes.strip():
        problems.append("material_notes пусто")
    if len(d.image_candidates.for_state_a) < MIN_IMAGES_PER_STATE:
        problems.append("нет картинок под state_a")
    if len(d.image_candidates.for_state_b) < MIN_IMAGES_PER_STATE:
        problems.append("нет картинок под state_b")
    if not d.web_confirmations:
        problems.append("нет ни одного подтверждения")
    return (not problems, problems)
```

`MIN_IMAGES_PER_STATE` — в конфиг (стартовое значение 3), не хардкод.

**Двойная защита:** D2 дополнительно hard-fail на досье, не прошедшем `can_freeze`
— даже если гейт как-то обошли. Дешевле упасть на входе в D, чем отдать пересказ
на редактуру и жечь E-слой впустую.

При провале гейта тема возвращается в банк с причиной, а не тихо едет дальше.

## Критерии приёмки

- [ ] Прогон с намеренно отключённым поиском картинок падает ЯВНО с внятной
      причиной, а не отдаёт пустой список.
- [ ] Различаются состояния «нашёл 0» и «не отработал» — видно в логе.
- [ ] На эссе Горалик по карточке «счётность» собираются картинки отдельно под
      «один кот» и под «пятьдесят котов».
- [ ] Пустое или полупустое досье НЕ проходит freeze; в ответе перечислены
      конкретные недостачи.
- [ ] D2, получив незамороженное/неполное досье, падает сразу, не пытаясь писать.
- [ ] Регресс: полное досье проходит freeze как раньше.

## Замечания

- Гейт вторичен по отношению к FIX-1: он ловит «C ничего не собрал», но не
  спасает от плохого тезиса. С универсальным claim досье может быть полным, а
  ролик всё равно выйдет моралью. Поэтому порядок именно такой.
- Не поддаваться соблазну «пропустить, если картинок мало — потом доберём на
  монтаже». Отбор на монтаже — это выбор ИЗ пачки, а не компенсация её
  отсутствия.
