# EDIT-A2 · Майнер тезисов (claim miner)

**Слой:** редакция / добыча (A2)
**Вход:** `source_map` (сегментированный источник — книга/научная статья/глава журнала по теории моды, истории дизайна, истории анимации)
**Выход:** `list[ClaimCard]`
**Зависит от:** A1 (сегментация) готова
**Блокирует:** B1 (скоринг), весь дальнейший пайплайн

---

## Зачем узел

Превращает источник не в «выжимку», а в набор **кандидатов на ролик**. Единица извлечения — не интересный факт, а **причинный тезис с разрывом ожидания**: утверждение о том, ПОЧЕМУ визуальное решение выглядит так, вместе с тем, что зритель по умолчанию думает иначе.

Ключевое отличие от «сделай саммари»: карточка без поля `counter_expectation` или без `visual_hint` невалидна и отбрасывается на парсинге. Тезис, который нельзя противопоставить наивному ожиданию и нельзя показать картинкой, — не материал для короткого видео, каким бы умным ни звучал.

---

## Контракт (Pydantic v2)

```python
from enum import Enum
from pydantic import BaseModel, Field, field_validator


class ClaimKind(str, Enum):
    causal = "causal"          # почему визуал такой (ЦЕЛЕВОЙ тип)
    corrective = "corrective"  # распространённое заблуждение опровергается
    origin = "origin"          # откуда взялась форма/приём
    # descriptive НЕ включён намеренно: "что изображено" — не наш жанр


class Citation(BaseModel):
    locator: str = Field(..., description="Глава/раздел/страница внутри источника")
    quote: str = Field(
        ..., min_length=1, max_length=300,
        description="Дословная цитата из источника, подтверждающая claim. НЕ пересказ."
    )


class Scope(BaseModel):
    period: str | None = Field(None, description="Год/эпоха, к которым относится тезис")
    region: str | None = Field(None, description="Гео/культурный контекст")
    author_or_work: str | None = Field(None, description="Автор, студия, бренд, конкретное произведение")


class ClaimCard(BaseModel):
    claim_id: str = Field(..., description="Стабильный slug, напр. bauhaus-sans-serif-cost")
    kind: ClaimKind

    claim: str = Field(
        ..., min_length=1, max_length=240,
        description="ОДНО утверждение о причине визуального решения. Одно, не составное."
    )
    counter_expectation: str = Field(
        ..., min_length=1, max_length=240,
        description="Что аудитория (дизайнеры/художники 20-40) по умолчанию думает об этом. "
                    "Именно контраст claim vs counter_expectation даёт крючок."
    )
    visual_hint: str = Field(
        ..., min_length=1, max_length=200,
        description="Конкретный объект/кадр, который ДОКАЗЫВАЕТ claim визуально. "
                    "Не абстракция ('модернизм'), а вещь ('обложка Vogue 1926, шрифт X')."
    )

    citation: Citation
    scope: Scope

    source_segment_id: str = Field(..., description="ID сегмента из source_map, откуда извлечён тезис")
    confidence: float = Field(..., ge=0.0, le=1.0,
                              description="Уверенность майнера, что тезис реально присутствует в сегменте")

    @field_validator("claim")
    @classmethod
    def _single_claim(cls, v: str) -> str:
        # эвристика против составных тезисов; жёсткая проверка — на скоринге B1
        for sep in [" и ", "; ", " также "]:
            if sep in v.lower():
                raise ValueError(
                    f"claim выглядит составным (найдено '{sep.strip()}'). "
                    "Разбей на отдельные карточки."
                )
        return v
```

**Правило hard fail на выходе узла:** карточки, не прошедшие валидацию Pydantic, не «чинятся» — логируются и отбрасываются. Лучше 6 валидных карточек с сегмента, чем 20 с пустыми полями.

## Системный промпт узла (черновик, доводить на реальных источниках)

```
Ты — редактор-разведчик научпоп-канала о визуальной культуре. Тебе дают
СЕГМЕНТ источника (глава книги / статья по теории моды, истории дизайна,
истории анимации). Твоя работа — найти в нём КАНДИДАТОВ НА КОРОТКОЕ ВИДЕО.

Канал отвечает на один вопрос: ПОЧЕМУ визуал выглядит именно так — не «что
это» и не «как это сделано». Причина, а не техника.

Извлекай только тезисы, для которых одновременно верно:
1. Это утверждение о ПРИЧИНЕ визуального решения (почему такая форма/цвет/
   шрифт/приём), либо опровержение расхожего заблуждения о визуале.
2. Есть ЧЁТКОЕ наивное ожидание, которому тезис противоречит. Если зритель
   и так это знает — пропусти.
3. Тезис можно ДОКАЗАТЬ конкретным изображением: назови конкретный объект,
   а не категорию.
4. В сегменте есть дословная фраза, подтверждающая тезис. Приведи её как есть.

Запрещено:
— выдумывать датировки, атрибуции, авторство. Если в сегменте нет — не пиши.
— пересказывать сюжет/содержание («в этой главе автор рассказывает...»).
— составные тезисы. Один claim = одна причина. Разбивай.
— оценочные общие места («это гениально», «это изменило искусство»).

На каждый валидный тезис заполни ВСЕ поля схемы ClaimCard. Если не можешь
заполнить counter_expectation или visual_hint — тезис не годится, пропусти его.

Верни ТОЛЬКО JSON-массив ClaimCard, без преамбулы и markdown-обёрток.
```

---

## Критерии приёмки

- [ ] На тестовом сегменте (глава из теории моды) узел выдаёт ≥3 валидных `ClaimCard` типа `causal`/`corrective`.
- [ ] Каждая карточка проходит Pydantic-валидацию; невалидные логируются с причиной, не попадают в выход.
- [ ] `counter_expectation` реально противоречит `claim` (проверить глазами на 5 карточках — не совпадает ли по смыслу).
- [ ] `visual_hint` называет конкретный объект, а не категорию (ручная проверка).
- [ ] `citation.quote` дословно присутствует в исходном сегменте (можно автоматом: подстрокой).
- [ ] Прогон на источнике БЕЗ причинных тезисов (напр. чисто биографическая глава) даёт пустой или короткий список — узел не галлюцинирует крючки.
- [ ] `claim_id` стабилен между прогонами одного сегмента (не рандом).

## Замечания к реализации

- Резать источник до узла (A1), не внутри. Целый том → модель обобщает, теряет частности, из которых и рождаются крючки.
- `confidence` не для фильтрации на этом шаге — для приоритезации на B1. Низкая уверенность ≠ плохой тезис, но требует более тщательного C1 (ресёрч).
- Тест на галлюцинации (пустой выход на биографической главе) — самый важный. Модель охотно придумывает контринтуитивные факты; ловить это надо здесь, до того как факт уедет в досье.
- `descriptive` намеренно вне enum. Соблазн добавить «просто интересные факты» велик — не поддавайся, это размывает жанр в сторону занятых конкурентов.
