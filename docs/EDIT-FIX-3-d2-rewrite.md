# EDIT-FIX-3 · D2 + таймкоды + удаление tight-прохода

**Приоритет:** 3 из 3 (после FIX-1 и FIX-2)
**Меняет:** промпт D2, бит-шаблон D1, конфиг длительности, E2, удаляет tight-проход
**Зависит от:** FIX-1 (`contrast_pair` + `mechanism_term` в карточке), FIX-2 (непустое досье)

---

## Диагноз

D1 рисовал правильную формулу на бумаге (hook → rupture → cause → proof →
transfer → coda), а D2 превращал каждый бит в перефраз `claim` и
`counter_expectation`. Намерение «показать улику» становилось «назвать улику
словами». Плюс три усугубляющих фактора:

- **Промпт D2 не требовал визуального разбора.** Требовал: факты из досье,
  `claim_id`, таймкоды. Не требовал: названные признаки объекта, контраст A/B,
  отложенная формула, запрет мета-связок.
- **Ранний payoff зашит в таймкоды.** При `target_duration_sec: 75` объяснение
  падало на 15–33 с — первая треть. Середина объясняла ДО того, как показала.
- **Tight-проход добивал.** Второй LLM сжимал уже плохой текст → ещё больше
  общих фраз, ещё меньше объекта на экране.

---

## Часть 1 — бит-шаблон D1 под норму канала

Заменить абстрактную формулу на норму, привязанную к полям карточки:

| Бит | Источник | Что обязано быть |
|---|---|---|
| 1. Хук-кадр | `object_anchor` | один объект, одна аномалия восприятия. Не «странно, но» |
| 2. Ложное объяснение | `counter_expectation` | «кажется, мило потому что…» — версия зрителя |
| 3. A/B | `contrast_pair.state_a` → `state_b` | два состояния одного объекта, названо что меняется |
| 4. Механизм | `mechanism_term` + `mechanism_explain` | один термин, объяснён через признаки на экране |
| 5. Формула | — | одна фраза, которую уносят |

Каждый бит ссылается на конкретное поле — D2 нечего изобретать.

## Часть 2 — промпт D2

Добавить жёсткие требования:

```
1. ОБЪЕКТ НА ЭКРАНЕ В КАЖДОЙ РЕПЛИКЕ. Каждая строка привязана к object_anchor
   либо к state_a / state_b. Реплика, под которую нечего показать, — брак.

2. ПРУФ = РАЗБОР ПРИЗНАКОВ, не ссылка на авторитет. Не «как писала [автор]»,
   а какие пропорции / какая фактура / какой момент во времени. Цитата
   источника — максимум ОДНА и как опора, не как доказательство.

3. ЗАПРЕЩЁННЫЕ СВЯЗКИ (стоп-лист): «странно, но», «формула простая»,
   «заметь», «через миг», «на самом деле всё просто», «а теперь представь».
   Это заглушки вместо наблюдения.

4. НЕ ПЕРЕСКАЗЫВАЙ claim. Тезис — то, к чему зритель должен ПРИЙТИ через A/B и
   механизм, а не то, что ему объявляют в трёх формулировках подряд.

5. ФОРМУЛА ТОЛЬКО В КОНЦЕ. Механизм и вывод — после того, как показаны оба
   состояния.
```

## Часть 3 — таймкоды и конфиг

- `target_duration_sec`: **40–50** (было 75).
- Механизм/формула — не раньше **55–60 %** длительности.
- Порядок битов в конфиге: хук → ложное объяснение → A/B → механизм → формула.

Ранний payoff чинится только вместе с содержанием середины: если середина
осталась общими словами, сдвиг сроков даст те же слова, просто позже.

## Часть 4 — убрать tight-проход

Отдельный «tight LLM» удаляется. Сжатие делает **только E6**, и только по
`RetentionReport` — адресно, а не вслепую. Причина: слепое сжатие маскирует
дыры в C/D вместо того, чтобы их показать.

## Часть 5 — E2 ловит причину, а не симптом

Добавить проверку: **в реплике назван объект / показано состояние**. Если нет —
`abstract`, severity ≥4, что автоматически даёт `passes=false`. Сейчас E2 верно
кричит про `abstract` и `front_loaded_payoff`, но правки некуда приложить —
после FIX-1/FIX-2 материал появится, и вердикт станет действенным.

## Критерии приёмки

- [ ] На карточке «счётность» сценарий содержит явный A/B: один кот → пятьдесят,
      названо что меняется в восприятии.
- [ ] Механизм назван ОДНИМ термином и объяснён через признаки, без перечисления
      фамилий.
- [ ] Формула/вывод — только в последней трети хронометража.
- [ ] Ноль вхождений из стоп-листа мета-связок (автопроверка).
- [ ] Каждая реплика привязана к `object_anchor` или к состоянию A/B.
- [ ] Tight-прохода нет в графе; сжатие только через E6 по отчёту E2.
- [ ] E2 на реплике без объекта ставит `abstract` severity ≥4.

## Эталон как приёмочный артефакт

В рамках этого тикета написать **руками** эталонные 40 секунд по карточке
«счётность» (один кот → пятьдесят котов → счётность как механизм → формула).
Не для публикации — как образец, к которому приближается вывод D2. Автотесты
проверяют формальные признаки; совпадение «по духу» проверяется сравнением с
эталоном глазами.

## Замечания

- Порядок важен: FIX-3 без FIX-1 бессмыслен. Если в карточке нет `contrast_pair`,
  требование «покажи A/B» упрётся в отсутствие материала, и D2 начнёт A/B
  выдумывать — это хуже пересказа, потому что выдуманный контраст выглядит
  убедительно.
- Стоп-лист мета-связок держать в конфиге и пополнять по мере прогонов: каждая
  новая заглушка, которую модель придумает вместо наблюдения, туда же.
